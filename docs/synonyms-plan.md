# Synonyms — description and implementation plan

This is a brief for a session that will implement the change. It is self-contained: read it,
then read the files named under "Where things are", and start.

## The problem

Maltese often has two words for one meaning: *jum* and *ġurnata* both mean "dzień / day".
Today the deck cannot hold both. The database has a unique constraint on `pl` and on `en`, and
`deckFromRows` drops any row that repeats a translation, so that "every question has one
answer". The second word of a pair can only be added with an invented qualifier in brackets.

The decision, taken with the owner: **keep it simple.**

- Two Maltese words may share a translation. Each stays a card of its own, with its own progress.
- When the Maltese word is typed, any word with that meaning counts as right.
- The letter pad does not change: it holds the letters of the word being asked, plus decoys as
  now. The pad is the hint for which of the two words is wanted. The other word can be typed
  only by chance, or on a hardware keyboard.
- After the answer, the card names the other word, so both get learned.

## Ground rules that must survive

- **The Maltese word stays unique and stays the key for saved progress** (`cardKey(dir, word.id)`,
  and `word.id` is the Maltese word). Nothing here may change a key, or progress is lost.
- **The grade goes to the card that was asked.** Typing *ġurnata* on the card for *jum* grades
  `x2mt:jum`, not `x2mt:ġurnata`. `Study.tsx`'s `answer` callback does not change.
- **No option list, tray, round or pair of visitors ever holds two words that share a
  translation.** `takeDistinct` (`src/lib/games.ts`) and `clash` (`src/lib/hive.ts`) already
  guarantee this by comparing text; do not weaken them.
- Rules live in `src/lib/` as pure functions on plain data, tested without a screen.
- The app's interface is in English; keep new labels in English, lower case, in the style of
  "plural:" and "form of:".

## For the learner

Polish/English → Maltese, typing: the card says "dzień · day". The pad shows the letters of
*jum* and some decoys, so *jum* is what can be spelled. Someone on a hardware keyboard who
types *ġurnata* gets "Correct" all the same. Under the answer the card says
"same meaning: ġurnata".

Polish/English → Maltese, flipping: the card says "dzień · day"; the back shows *jum* and
"same meaning: ġurnata". The learner grades themselves as now.

Maltese → Polish/English: nothing changes on the question. *jum* is asked, the back shows
"dzień · day" and "same meaning: ġurnata".

Both cards exist, so "dzień" can come up twice in one session, once for each word. That is
accepted.

## What counts as a synonym

Two different words are synonyms **for the question as it is shown**: every translation on
the card is the same text for both.

| `show` | Synonyms of a word |
|--------|--------------------|
| `both` | Words with the same `pl` and the same `en`. |
| `pl` | Words with the same `pl`. |
| `en` | Words with the same `en`. |

Comparison is exact string equality (the deck is already trimmed). The search covers the whole
deck (`WORDS`), not just the chosen topic and not just the kinds of card switched on in
Settings: a correct word is correct wherever it lives.

In a well-kept deck the three rows give the same answer, because words that share one
translation share the other (step d adds a test for the shipped deck). The rule by `show`
only matters when the database holds a half-finished edit, and then it still does the honest
thing: it accepts every word that answers the question on the screen.

  const t: Triple = [clean(w.mt), clean(w.pl), clean(w.en)];

## b — Rules: `src/lib/answer.ts` and `src/lib/answer.test.ts`

**`synonymsOf`.** New, exported:

```ts
/**
 * The other words that answer the same question as `word`: those whose translations, as far
 * as the card shows them, are the same text. In deck order.
 */
export function synonymsOf(word: Word, words: readonly Word[], show: ShowLang): Word[] {
  return words.filter(
    (w) => w.id !== word.id && (show === 'en' || w.pl === word.pl) && (show === 'pl' || w.en === word.en),
  );
}
```

Import both types with `import type` (`Word` from `./words`, `ShowLang` from `./store`), so no
module cycle is created.

**`checkAnswer`.** Rename the present function body to an unexported `checkOne(typed, expected)`
and leave its rules untouched. The exported function takes the best verdict over every right
word:

```ts
const RANK: Record<Verdict, number> = { wrong: 0, close: 1, correct: 2 };

/**
 * Scores a typed Maltese answer against the word asked and any `alsoRight` words with the
 * same meaning: the best verdict among them.
 */
export function checkAnswer(typed: string, expected: string, alsoRight: readonly string[] = []): Verdict {
  let best: Verdict = 'wrong';
  for (const e of [expected, ...alsoRight]) {
    const v = checkOne(typed, e);
    if (RANK[v] > RANK[best]) best = v;
  }
  return best;
}
```

Move the existing doc comment (correct / close / wrong) to `checkOne`. With `alsoRight` left
out the behaviour is exactly as before, so every existing call and test stays valid.

**Tests to add** (`src/lib/answer.test.ts`):

- `checkAnswer('ġurnata', 'jum', ['ġurnata'])` is `correct`; so is `'Ġurnata '`, and
  `'il-ġurnata'` (the article rule applies to synonyms too).
- `checkAnswer('gurnata', 'jum', ['ġurnata'])` is `close` (missing dot).
- `checkAnswer('lejl', 'jum', ['ġurnata'])` and `checkAnswer('', 'jum', ['ġurnata'])` are `wrong`.
- `checkAnswer('jum', 'jum', ['ġurnata'])` is `correct`.
- `synonymsOf` on hand-made words: with `both`, a word sharing `pl` and `en` is returned and a
  word sharing only `pl` is not; with `pl`, both are; with `en`, only the one sharing `en`;
  never the word itself; an empty list when nothing matches.

## Why the games need no change

Every game decides right and wrong by `word.id`, never by the text on a label, and every place
that puts several words on the screen already refuses two that share `mt`, `pl` or `en`:

| Game | Why it is safe |
|------|----------------|
| Speed round, Bouncy bee | `makeQuestion` → `takeDistinct`: a synonym of the answer is never an option. |
| Protect the hive | `canEnter` and `fillTray` use `clash`: synonyms are never on the field or in the tray together. |
| True or sting | `impostorFor` skips words that `clash` with the visitor, so a "false" meaning is never a true one. |
| Match pairs | `pickDistinct`: a round never holds both. |
| Queen's orders | `makeOrder` → `takeDistinct` over one verb's forms. |
| Infinite typing | Uses `TileCard`; gets the new behaviour from step c. |
| Honeycomb spell, Spider web | One hidden word; its letters, or the number of cells, show which word it is. |
| Watch the flowers | Shows a word and its meaning; asks nothing. |

Known and accepted: in Honeycomb spell and Spider web a learner who thinks of the other word
loses a try before the letters put them right.

## For the owner, after the code is merged

The app and the database can be updated in either order. An older copy of the app that meets
a repeated translation simply leaves the second word out.

1. Supabase → SQL Editor: run `supabase/migrations/20261113000150_words_synonyms.sql` once.
   To check, this should list only `words_mt_key`:

   ```sql
   select conname from pg_constraint
   where conrelid = 'public.words'::regclass and contype = 'u';
   ```

2. Add the new words, placed right after *jum* and its plural:

   ```sql
   insert into public.words (topic_id, mt, pl, en, position)
   select topic_id, 'ġurnata', pl, en, position + 2 from public.words where mt = 'jum';

   insert into public.words (topic_id, mt, pl, en, position, plural_of)
   select topic_id, 'ġranet', pl, en, position + 2, 'ġurnata' from public.words where mt = 'jiem';
   ```

3. Do not run the seed file again: it is for an empty database only.

From then on a synonym is added like any other word, in the Table Editor, with the same `pl`
and `en` as the word it matches.
